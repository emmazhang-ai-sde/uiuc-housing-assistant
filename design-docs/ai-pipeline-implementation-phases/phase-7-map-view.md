# Phase 7 — Map View

## Goal

Add a Map tab alongside the existing Cards and Table views. Users see all matched listings plotted geographically on a UIUC-area map; clicking a pin shows a mini card with address, beds, price, and availability. A follow-on proximity filter lets users search by named campus landmark (e.g. "near Grainger").

For library/tile/geocoding decisions, see `design_docs/map-library-options.md`.

**Stack:** `react-map-gl` + MapLibre GL · MapTiler or OpenFreeMap tiles · Nominatim geocoding

---

## Implementation Steps

### Step 1 — Add `lat`/`lng` columns to SQLite

The `listings` table in `snapshots/listings_2026-06-13.db` does not yet have coordinates. We store them in SQLite (rather than writing directly to Chroma) because SQLite is the source of truth — if `ingest.py` is re-run after a future scrape, it reads from SQLite and overwrites Chroma metadata, which would erase any lat/lng written directly to Chroma.

```bash
sqlite3 snapshots/listings_2026-06-13.db "ALTER TABLE listings ADD COLUMN lat REAL; ALTER TABLE listings ADD COLUMN lng REAL;"
```

Also update `pipeline/normalize.py` to include `lat REAL, lng REAL` in the `CREATE TABLE listings` statement, so future scrape runs produce a DB that already has the columns.

Verify the columns were added:

```bash
sqlite3 snapshots/listings_2026-06-13.db "PRAGMA table_info(listings);"
```

### Step 2 — Write the geocoding script ([`pipeline/geocode.py`](../pipeline/geocode.py))

`lat`/`lng` data does not come from the scrapers — it doesn't exist yet anywhere in the project. The scrapers only capture address strings (e.g. `"309 E Green St, Champaign, IL"`). Coordinates are generated by sending each address to **Nominatim (OpenStreetMap's free geocoding API)**, which returns the corresponding latitude and longitude.

This is a one-time batch job. It reads every distinct address from SQLite, calls Nominatim, and writes the result back.

Run: `python -m pipeline.geocode`

Addresses in the DB already contain the full city/state/zip, so they are passed to Nominatim as-is — no city suffix is appended. The script is safe to re-run; it skips rows where `lat IS NOT NULL`. The 1.1s sleep respects the Nominatim rate limit — ~410 addresses takes under 8 minutes.

#### Address cleaning (`clean_address`)

Raw addresses from the scrapers are not always clean. A `clean_address()` helper runs before each Nominatim call. Rules applied in order:

| Pattern | Example | Fix |
|---|---|---|
| Missing zip stored as string `"None"` | `913 S. Third St, Champaign, IL None` | Strip `\s+None\b` |
| Em-dash descriptor suffix | `60 E Green – Roommate Matching Special!` | Strip everything from `–` onward |
| ` - NOTE` suffix where NOTE is not a number or compass direction | `75 E. Armory, Champaign - Immediate Move in` | Strip ` - ` and everything after |
| `-ALLCAPS` tag without spaces | `25 E John, Champaign-ROOMMATE MATCHING` | Strip `-[A-Z]{2,}.*` |
| Slash-joined multi-address | `1108 S. Lincoln/810 W. Indiana, Urbana` | Keep only the first segment |
| Unit designators | `204 N Neil St Unit #B` | Strip `Unit #B` |
| Missing state | `901 W. Western Ave, Urbana` | Append `, IL` only — do not add a city, as one may already be present |

**Bug history:** two bugs were found after the first run:
- *Bug 1*: the original regex `r',\s*None$'` never matched because the scraper writes `IL None` with a space, not a comma. Fixed to `r'\s+None\b'`.
- *Bug 2*: the state fallback appended `, Champaign, IL` even when a city was already in the address (e.g. `Urbana`), producing a broken query. Fixed to append `, IL` only.

#### Hardcoded coordinates (`MANUAL_COORDS`)

Some addresses Nominatim cannot resolve even with a cleaned query — either because the building name has no street number, or because Nominatim mismatches the address to another town in Champaign County (e.g. Fisher, St. Joseph) instead of the city of Champaign. These are handled via a `MANUAL_COORDS` dict in `geocode.py`, keyed by a substring of the raw address. `geocode()` checks this dict before calling Nominatim.

| Key | Raw address(es) matched | Coordinates | Resolution |
|---|---|---|---|
| `"W. John"` | `1017, 1019 W. John, Champaign` | `(40.10892, -88.26153)` | Nominatim (standard query) |
| `"715 Balboa"` | `715 Balboa Dr., Champaign, IL 61820` | `(40.09484, -88.25396)` | Nominatim: `"Balboa Road"` spelling worked; `"Balboa Dr."` didn't |
| `"717 Balboa"` | `717 Balboa Dr., Champaign, IL 61820` | `(40.09484, -88.25401)` | Same |
| `"813 Balboa"` | `813 Balboa Dr., Champaign, IL 61820` | `(40.09485, -88.25676)` | Same |
| `"901 W. Western"` | `901 W. Western Ave, Urbana` | `(40.11188, -88.21973)` | Nominatim: `"Western Avenue"` spelling worked; `"W. Western Ave"` didn't |
| `"302-310 S. 1st"` | `302-310 S. 1st-Midtown Plaza, Champaign` | `(40.11394, -88.23826)` | Nominatim: required structured `street=…&city=Champaign&state=IL` params; freeform query matched Fisher IL |
| `"302 S. 1st"` | `302 S. 1st-Midtown Plaza – Lake Facing Suites` | `(40.11394, -88.23826)` | Same (same building as above) |
| `"310 S. 1st"` | `310 S. 1st-Midtown Plaza – Move-in Today!` | `(40.11304, -88.23829)` | Same |
| `"309 S. 1st"` | `309 S. 1st Midtown Plaza West` | `(40.11321, -88.23906)` | Same |
| `"Stoneway Condos"` | `Stoneway Condos, Champaign, IL 61822` | `(40.13209, -88.30133)` | No street number; resolved to 3341 Stoneway Ct via Nominatim |
| `"Windsor Duplexes"` | `Windsor Duplexes, Urbana, IL 61801` | `(40.09383, -88.19336)` | No street number; resolved to 907 E Harding Dr via web search + Nominatim |

**Note on key ordering:** `"302-310 S. 1st"` must appear before `"310 S. 1st"` in the dict — the former is a substring of the latter's target address, so if `"310 S. 1st"` matched first it would also consume the `302-310` listing. Python 3.7+ dicts preserve insertion order, so the order in `geocode.py` is load-bearing.

**Still unresolved:** `1107 S. Fourth - Gregory Towers, Champaign` — Nominatim matches St. Joseph IL instead of Champaign. Needs manual lookup.

### Step 9 — Backend proximity filter (haversine)

Once `lat`/`lng` are in Chroma metadata, location-based filtering can be implemented as a post-retrieval step in `rag/rag_chain.py`. Chroma does not support distance-based where clauses natively, so filter after `get_filtered_docs()` returns:

```python
import math

LANDMARK_COORDS = {
    "grainger": (40.1125, -88.2269),
    "main quad": (40.1072, -88.2270),
    "bif": (40.1020, -88.2310),
    "arc": (40.1016, -88.2370),
    "green street": (40.1096, -88.2100),
}
PROXIMITY_RADIUS_MI = 0.5

def haversine_mi(lat1, lng1, lat2, lng2) -> float:
    R = 3958.8
    dlat = math.radians(lat2 - lat1)
    dlng = math.radians(lng2 - lng1)
    a = math.sin(dlat/2)**2 + math.cos(math.radians(lat1)) * math.cos(math.radians(lat2)) * math.sin(dlng/2)**2
    return R * 2 * math.asin(math.sqrt(a))

def filter_by_location(docs, location_hint: str) -> list:
    hint = location_hint.lower()
    target = next((v for k, v in LANDMARK_COORDS.items() if k in hint), None)
    if not target:
        return docs
    tlat, tlng = target
    return [
        doc for doc in docs
        if doc.metadata.get("lat") and doc.metadata.get("lng")
        and haversine_mi(doc.metadata["lat"], doc.metadata["lng"], tlat, tlng) <= PROXIMITY_RADIUS_MI
    ]
```

Call `filter_by_location(docs, merged.get("location_hint", ""))` in `backend/main.py` after `get_filtered_docs()`.

## Bug fixes discovered during Phase 7

### "Individual Lease Special" mislabelled as Studio

**Root cause:** `beds = 0` is overloaded in the scraped data. True studios (e.g. `Luxury Studio`) and individual-lease / roommate-matching listings both arrive with `beds = 0`, because the scraper can't extract a bedroom count for per-person pricing. All three views hardcoded `beds === 0 → "Studio"`, which is wrong for the latter.

**Example:** `60 E Green – Roommate Matching Special!` has `unit_type = "Individual Lease Special"`, `beds = 0`, `price = $850/person`. The DB text literally stores `"0 bed, 1 bath"`.

**Fix:** Added `bedsLabel(beds, unitType)` to `frontend/lib/availability.ts`. It returns `"Studio"` only when `unit_type` matches `/studio/i`; otherwise returns `""` for `beds === 0`. Updated all three call sites:

| File | Old | New |
|---|---|---|
| `ListingCard.tsx` | `beds === 0 ? "Studio" : ...` | `bedsLabel(listing.beds, listing.unit_type)` |
| `SummaryTable.tsx` | `bedsStr(beds)` — ignored unit_type | `bedsStr(beds, unitType)` → delegates to `bedsLabel` |
| `MapView.tsx` popup | `beds === 0 ? "Studio" : ...` | `bedsLabel(popup.beds, popup.unit_type)` |

Individual lease listings now show only the `unit_type` string with no beds suffix.
